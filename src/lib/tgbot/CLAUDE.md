# Клиентский бот @KMOTORS_form_bot — правила ядра

Решение владельца 27.11.2026: бот сам ведёт клиента (меню, карточка машины с ценой,
вопросы кнопками, запчасти по номеру), а переписка с менеджером идёт через закрытую
форум-группу — тема на каждого клиента. Цель — не терять лидов.

## Как устроено

| файл | что |
|---|---|
| `flows.ts` | сторона клиента: `/start` (car_, sold_, part_, website), меню, кнопки `b:*`, сообщения |
| `inbox.ts` | сторона менеджера: тема клиента, шапка с кнопками статуса `m:*`, пересылка в обе стороны |
| `store.ts` | таблица `tg_bot_clients` (`sql/047_tg_bot_clients.sql`) |
| `reminders.ts` | кому напомнить / кому «дожим»; крон `/api/bot/reminders` (`bot-reminders`, каждые 10 мин) |
| `draft.ts` | черновик ответа от Claude (`claude-opus-5-5`, effort low) по фактам из базы и истории |
| `texts.ts` | тексты RU/EN; FAQ и этапы покупки — из словаря `/buy`, не дублировать |

Вход — `src/app/api/telegram-webhook/route.ts`: группа менеджеров и личка клиентов
разбираются ДО гейта `isAdmin`; админские команды (`/generate`, SEO-кнопки) не тронуты.

## Правила

- ⚠️ **Сообщение клиента копируется менеджеру ВСЕГДА, первым делом** (`relayFromClient`),
  что бы бот ни ответил сам. До 27.11.2026 личные сообщения не-админов молча отбрасывались
  гейтом `isAdmin`, хотя бот писал «просто напишите в этот чат».
- **Цены считает код сайта, не текст**: машина — снимок `cars_seen` + `carPriceKrw` +
  `getFx("car")`; деталь — `parts_products` + `pricing.ts` + `getFx("market")`. Encar бот
  не дёргает. Сроки доставки и цену «под ключ» бот не называет — это менеджер.
- Чат группы — только `telegramChatId("inbox")` (`TELEGRAM_INBOX_CHAT_ID`). Не задан или
  Telegram отказал в теме — фолбэк в чаты `admins`, как было до бота.
- Сообщение менеджера в теме, начатое с `!` или `/`, — заметка, клиенту не уходит.
- Модуль не бросает: сбой базы или Telegram не должен ронять вебхук (Telegram ретраит).
- Ссылку `tg://user` — только в тексте, не кнопкой (`BUTTON_USER_PRIVACY_RESTRICTED`
  роняет всё сообщение).

## Черновики Claude (решение владельца 28.11.2026)

- Claude **только пишет черновик**, клиенту отправляет человек кнопкой «✅ Отправить клиенту»
  в теме. Автоответ клиенту без человека — один: «нерабочее время, ответим в рабочий день»
  (ночь 23–08 KST и выходные KST, через 30 мин без ответа), и в нём нет цифр.
- Черновик готовится через 20 с после последнего сообщения клиента (`after()`), на серию
  сообщений — один. Номер детали бот обрабатывает сам, черновик там не делается.
- Факты для черновика — `buildFacts`: снимок машины + цена по KB, деталь + `pricing.ts`, ответы
  на вопросы бота, FAQ и этапы со страницы /buy. Сроки, растаможку, наличие модель НЕ называет.
- История — `tg_bot_messages` (клиент и менеджер), черновики — `tg_bot_drafts` (`sql/048`).
  Отправка черновика забирает его атомарно (`claimDraft`): двойной клик не шлёт ответ дважды.
  Ответ менеджера в теме снимает все ждущие черновики клиента.
- Нет `ANTHROPIC_API_KEY` — черновиков нет, остальное работает.

## Настройка

Сделано 27.11.2026: группа «K-Axis · Заявки клиентов» (частная, темы включены, бот —
админ с «Управлением темами»), `TELEGRAM_INBOX_CHAT_ID=-1005960153445` в Coolify,
таблица из `sql/047` в базе, задача `bot-reminders` в Coolify. Публичную группу постера
(@avto_korea_chats) под переписку НЕ использовать: её может читать любой по ссылке.

Если настраивать заново:

1. Создать закрытую группу, включить «Темы» (Topics).
2. Добавить бота админом с правом «Управление темами».
3. Узнать id группы: открыть её в web.telegram.org — в адресе `#-100…`, это и есть id.
   Задать в Coolify `TELEGRAM_INBOX_CHAT_ID=-100…`.
4. Выполнить `sql/047_tg_bot_clients.sql` в Supabase → SQL Editor.
5. Coolify → Scheduled Tasks: `bot-reminders`, `node ./scripts/cron/run.mjs bot-reminders`,
   `*/10 * * * *`.

Тесты — `tests/telegram/tgbot.spec.ts`.
