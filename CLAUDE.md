# CLAUDE.md

Инструкции для Claude Code в этом репозитории.

Разборы инцидентов вынесены в [docs/postmortems.md](docs/postmortems.md), отложенные
вопросы — в [docs/open-questions.md](docs/open-questions.md). Здесь только то, что нужно
знать до того, как трогать код.

## Что это

Full-stack e-commerce на kmotors.shop (бренд в интерфейсе — K-Axis, мягкий ребрендинг,
домен прежний). Два каталога: подержанные корейские авто (источник Encar) и оригинальные
запчасти Hyundai/Kia/Genesis. Свой AI SEO-пайплайн, оплата через PayPal, операции через
Telegram. Полный список фич и переменных окружения — README.md.

## Проверка — ОБЯЗАТЕЛЬНА перед тем, как считать задачу сделанной

Сборка ошибок НЕ ловит: в `next.config.ts` стоят `eslint.ignoreDuringBuilds: true` и
`typescript.ignoreBuildErrors: true`. Прошедшая сборка не доказывает ничего. Всегда:

```bash
npm run lint
npx tsc --noEmit
```

Тестов в проекте нет — не рассчитывать на `npm test`.

### Застрял — сообщи сразу, не молчи

lint + tsc обязательны всегда. Всё остальное (браузерная проверка, дев-сервер, скриншоты,
скрипты, внешние API) — если инструмент виснет, отваливается по таймауту или требует
обходных путей, ОСТАНОВИСЬ после ВТОРОЙ неудачной попытки и напиши пользователю: что не
работает, что уже сделано, какие есть варианты. Не уходить в молчаливый цикл обходных
решений — это сжигает время и деньги, а пользователь узнаёт постфактум.

Типовые случаи: панель браузера скрыта (`document.visibilityState === "hidden"` →
скриншоты чёрные; проверять через DOM/read_page или попросить открыть панель), дев-сервер
не поднимается, Encar/Supabase не отвечают.

Правило простое: сама работа важнее её демонстрации. Код готов и проверен через lint/tsc —
доложить об этом и о проблеме с проверкой, дальше решает пользователь.

## Деплой и прод — ЧИТАТЬ ПЕРВЫМ

- Каждый push в `main` запускает автоматический редеплой прода (Coolify на VPS). `git push`
  в main — это действие «выкатить», а не «сохранить».
- Supabase развёрнут на том же VPS и является ЖИВОЙ ПРОДАКШЕН-БАЗОЙ. `.env` в репозитории
  смотрит на неё. Любой SQL, любой скрипт с данными, любая команда supabase CLI бьёт прямо
  в прод. Отдельной staging-базы нет.
- Coolify на VPS — единственный живой прод. `vercel.json` остаётся ТОЛЬКО ради headers,
  `netlify.toml` — мёртвый зеркальный конфиг, `output: 'standalone'` для Docker-сборки.
  Строка «Vercel primary» жила в этом файле до 07.2026 и стоила месяца молчащего блога
  ([постмортем](docs/postmortems.md)) — не восстанавливать.

## Жёсткие правила

### Работа с репозиторием

- НИКОГДА не делать `git push` — ни в main, ни в любую ветку — без явного подтверждения
  пользователя в текущей сессии. Закоммитить локально, затем остановиться и доложить.
- Вся работа идёт в feature-ветках. Не коммитить прямо в main.
- Навигация по коду: использовать Serena (`find_symbol`, `find_referencing_symbols` и
  т.д.) вместо Grep/Read. Grep — только если Serena недоступна.

### Данные и база

- Не запускать скрипты из `scripts/` или `sql/` без явного подтверждения — они бьют в
  продакшен-Supabase. Запускаются как `npx tsx --env-file=.env scripts/x.ts`, большинство
  резюмируемые/идемпотентные (логи прогресса вроде `scripts/.image-migration.log`); сперва
  прочитать шапку скрипта — там переменные (LIMIT, CONCURRENCY, DELAY_MS).
- Не менять схему БД, RLS-политики и не выполнять разрушительный SQL без явного
  подтверждения.
- `parts_staging` закрыта для кода приложения — это буфер загрузки. Приложение читает
  `parts_products`.
- Не расширять `parts_fitment` / `parts_vehicle_models` (легаси). Вся новая работа по
  совместимости — в `part_vehicles` + `vehicles`.
- Любой `.range()`/`.limit()` по неуникальному ключу обязан иметь вторым ключом
  `.order("id")` — иначе строки пропадают между страницами
  ([постмортем](docs/postmortems.md)).

### Цены и курсы

- **Запчасти:** хранятся в KRW, показываются в USD через `src/lib/pricing.ts` (`formatUsd`,
  фиксированный `PRICE_MARKUP`). Не форматировать и не конвертировать цены на месте.
- **Авто:** другая модель, `pricing.ts` НЕ применяется. Главная цена в карточке — воны
  (KRW); ₽ (ru) / $ (остальные языки) показываются ниже как справка и считаются по ЖИВОМУ
  курсу из `src/utils/getCurrencyRates.ts` (кеш 24ч).
- Никогда не зашивать курс константой.
- Источники курсов РАЗНЫЕ и независимые: рубль — ЦБ РФ, доллар — frankfurter. Не сводить к
  одному источнику, не проверив, что он отдаёт ОБЕ валюты; frankfurter не отдаёт RUB
  вообще. `?? FALLBACK` на внешнем курсе — это не подстраховка, а место, где расхождение
  становится невидимым; падение на фолбэк должно логироваться
  ([постмортем](docs/postmortems.md)).
- На любом маршруте, который рендерит ЦЕНУ, `revalidate` не выше 86400: курс запекается в
  HTML в момент рендера, и если страница не перерендеривается, кеш курса опросить некому.

### Изображения

Никогда не читать `image_url` напрямую — только через `src/lib/partImage.ts`
(`resolvePartImage` / `withCleanImage`; предпочитает `image_storage_url`).

### SEO

- Canonical и hreflang всегда идут через `makeAlternates(lang, path)` (`src/lib/seo.ts`).
  `trailingSlash` = false, поэтому путь `"/"` даёт URL с 308-редиректом, и Google
  отбрасывает такой тег — главная передаёт `""`. То же правило в
  `src/app/sitemap-main.xml/route.ts` (`buildUrl`) и во внутренних ссылках на языковой
  корень.
- SEO-пайплайн никогда не трогает живые данные до гейта одобрения в Telegram — этот
  инвариант не менять.

### Внешние вызовы

- Обращения к Encar не должны бросать исключений НИКОГДА. Каждый вызов в `api.encar.com`
  идёт через хелпер, который ловит, падает на фолбэк и возвращает типизированный пустой
  результат (`getCars` в `src/components/Catalog/Row/utils/service.ts`, `fetchNav` в
  `src/components/Catalog/Filter/FilterService/index.ts`). Всегда: `AbortSignal.timeout`
  (8s основной / 20s прокси на Render, он холодно стартует), проверка `res.ok`, try/catch
  ВОКРУГ ФОЛБЭКА ТОЖЕ. Не добавлять голый `fetch` к Encar в компоненте.
- Гейты крон-роутов обязаны быть FAIL-CLOSED:
  `if (!secret || req.headers.get("x-poster-secret") !== secret) return 401`.

## Архитектура

### Роутинг и i18n

- `src/app/[lang]/...` — все публичные страницы. `[lang]` ∈ `ru | en | ka | ar`
  (`src/lib/lang.ts`).
- Разрешение URL без префикса: cookie → Accept-Language → cf-ipcountry → по умолчанию `ru`
  (`src/lib/lang.ts`, применяется в `middleware.ts`).
- Локаль `ko` отключена (301 → `/en`). `LOCALIZATION_GUIDE.md` её всё ещё перечисляет —
  документ устарел; доверять `src/lib/lang.ts` / `src/lib/i18n.ts`
  (`SUPPORTED = ['ru','en','ka','ar']`).
- i18n собирается на каждый запрос, а не бандлится глобально: `src/lib/i18n.ts` поднимает
  инстанс i18next с активным языком и фолбэком `en` (это спасает от рассинхрона гидрации и
  раздувания бандла). Переводы: `src/locales/<lang>/{common,cars}.json`.
- `middleware.ts` дополнительно делает: блокировку ботов и Electron-скраперов, 308-редиректы
  легаси-URL запчастей (`PN--name-slug` → `PN`), cookie-гейт `/admin`, отправку
  first-party аналитики в `/api/track`, 410 на устаревшие проиндексированные пути и
  серверное обновление сессии Supabase.

### Каталог авто (на данных Encar)

Вход: `/[lang]/catalog` (листинг) и `/[lang]/catalog/[id]` (карточка). Данные тянутся из
`api.encar.com` на каждый запрос через `src/lib/vehicle.ts` (`fetchVehicleData`);
локальной копии данных о машинах нет.

**Листинг деградирует, а не падает.** `getCars` возвращает `{ data, count, failed }` и
никогда не реджектится; `CarsRow` рисует три разных состояния — машины, «ничего не
найдено» (пустой результат) и «временно недоступно» (`failed: true`) — во всех четырёх
локалях. 404 от Encar означает кривой запрос (например мусор в `?action=`), а не аварию:
он ложится в пустое состояние, не тратя второй поход через прокси.
`src/app/[lang]/catalog/error.tsx` — сегментная граница ошибок, чтобы неожиданный throw
сохранил layout, а не проваливался в корневой `app/error.tsx`.

`page.tsx` и `CarsRow` обязаны звать `getCars` с ИДЕНТИЧНЫМИ аргументами — тот же запрос,
тот же `pageSize`, тот же offset (`(page-1)*pageSize`). JSON-LD `ItemList` должен описывать
список, который реально видит посетитель, а совпадение аргументов позволяет Next схлопнуть
два вызова в один запрос к Encar.

#### Карточка авто — метаданные

Файл `src/app/[lang]/catalog/[id]/page.tsx`. Три связанных инварианта:

1. `title` и H1 обязаны совпадать. Google берёт H1 как основной источник, переписывая
   заголовок в выдаче; английский H1 под локализованным title провоцирует переписывание.
   Оба несут модель + комплектацию + год + локализованное «из Кореи» в одном порядке слов.
2. Цена в сниппете обязана совпадать с ценой, которую видит посетитель (ru → ₽, остальные
   → $). Порядок: модель → год → гео → цена. `ka` — исключение, там цена перед гео:
   грузинские глифы широкие (Google режет по ширине в пикселях), а гео-слова в целевом
   запросе нет.
3. В JSON-LD `Offer` остаётся `priceCurrency` KRW — оно должно совпадать с главной ценой в
   `CarDetailSidebar`, а не со справочной конвертацией.

Дальше:

- Корейские слова из спецификации (`carShape` «세단 4도어», `transmissionName` «오토»,
  `fuelName` «LPG(일반인 구입)») обязаны проходить через `src/lib/carLabels.ts`. У
  `generateMetadata` нет инстанса i18next (i18n поднимается на запрос), поэтому он читает
  `cars.json` напрямую. Правило: если слово осталось хангылем после подстановки — выкинуть
  всё поле. Пустое поле лучше корейского в сниппете Google.
- `manufacturerEnglishName` приходит склеенным: `ChevroletGMDaewoo`,
  `Renault-KoreaSamsung`, `KG_Mobility_Ssangyong`. Всегда показывать через
  `normalizeBrand()`. Он питает H1, title, description и `brand` в JSON-LD.
- H1 несёт префикс title слово в слово (модель + комплектация + год + локализованное «из
  Кореи»), затем приглушённая подстрока «пробег · коробка». Удлинять хвост можно; менять
  общий префикс — значит ломать инвариант 1.
- Использовать `formatYear()` («2024») в title/H1/description. `formatDate()` возвращает
  формат регистрации Encar «YY.MM» — только для строк спецификации; покупателю вне Кореи
  это читается как шум.
- Суффикс «| K-Axis» из глобального шаблона title подавлен на карточках через
  `title: { absolute }` — экономит ~9 символов из бюджета в ~60.

#### Карточка авто — сознательные компромиссы рендера, НЕ «чинить» как баги

Два блока намеренно исключены из первой отрисовки. Оба измерены и выбраны осознанно;
предложение отрендерить их на сервере — это продуктовое решение, а не отчёт о дефекте.

- Названия опций (`OptionsRow`) лежат в свёрнутых аккордеонах Radix и в серверном HTML их
  НЕТ — есть только счётчики по категориям («Стандартные опции 37, Комфорт 11…»). Encar
  присылает коды («001», «004», …), они резолвятся по словарю из 218 записей в
  `OptionsRow/data.ts`. Свёрнутость + ленивый маунт — это то, что держит первую отрисовку
  дешёвой. Известная цена в SEO: ~37 реальных названий опций на машину не попадают в HTML.
- `RecommendedCars` грузится по скроллу (IntersectionObserver → `/api/recommended`). Боты
  поэтому видят `<h2>` с пустой каруселью и не получают из карточки ни одной внутренней
  ссылки. Принято по той же причине.

Контраст — `DetailInfo` (спецификация + история аварий и владельцев): его ПЕРЕНЕСЛИ на
сервер (`src/lib/vehicleRecord.ts` + `DetailInfoSection.tsx` за Suspense), потому что это
самый уникальный контент карточки. Suspense сохраняет быструю первую отрисовку, а блок всё
равно оказывается в том же HTTP-ответе — вот образец, если что-то из перечисленного выше
когда-нибудь будут переносить на сервер.

#### Карточка авто — картинки

Галерея и лайтбокс — намеренно разные пути: лайтбокс (yet-another-react-lightbox,
`dynamic ssr:false`, свои `LIGHTBOX_WIDTHS` до 1920) не грузит ничего, пока пользователь
его не откроет. Проверено. Размеры для мобильных и превью посчитаны верно, для десктопа —
нет; детали в [docs/open-questions.md](docs/open-questions.md).

#### Проданная машина

Проданная машина = 404 от Encar = `fetchVehicleData` возвращает `null`.

`fetchVehicleData` отличает «продана» (Encar 404 → `null`) от «апстрим лежит» (бросает
`VehicleUpstreamError`). `generateMetadata` ставит `noindex` ТОЛЬКО для случая продажи.
Никогда не схлопывать эти две ветки в `catch(() => null)`
([постмортем](docs/postmortems.md)).

При `data === null` рендерится `SoldCarPage`: снимок из `cars_seen` (фото, характеристики,
перечёркнутая прежняя цена), кнопка подписки deep-link'ом в бота и мессенджеры с готовым
текстом. `notFound()` на этом маршруте остался только для непустого, но кривого ответа.
Раньше в обеих ветках стоял `notFound()`, и весь входящий поисковый трафик на проданные
машины (сотни URL в индексе) попадал в пустую заглушку — при том, что посетитель тут самый
квалифицированный из возможных, он искал конкретную модель.

- ⚠️ `noindex` остаётся. Страница живёт ради людей, уже пришедших из индекса, а не ради
  ранжирования; вернём индексацию — вернутся сотни «дубликатов без канонического» в GSC.
  Выставляется независимо, в `generateMetadata`, и от рендера не зависит.
- Имя собирается ТОЛЬКО из английских полей снимка через `normalizeBrand`. Нет их (снимок
  из бэкфилла) — показывать нейтральный заголовок, а не хангыль.
- Снимка нет вовсе — блок похожих не рендерится, страница деградирует до «объявление
  снято» + подписка + каталог.
- Похожие подбираются в `src/lib/similarCars.ts`: марка + модельная группа + год ±1 + цена
  ±15%, корейскими именами из снимка. Собственный `recommend/{id}` у Encar для этого не
  годится — он привязан к живому объявлению.
- ⚠️ Не восстанавливать хардкод `<meta name="robots" content="index, follow">`, который
  когда-то стоял в `src/app/layout.tsx` ([постмортем](docs/postmortems.md)).

#### cars_seen — снимки машин Encar

Файлы: `src/lib/carsSeen.ts`, `sql/035_cars_seen.sql`.

Encar держит объявление только пока машина продаётся: после продажи
`/v1/readside/vehicle/{id}` отдаёт 404, и от машины не остаётся ничего — ни марки, ни
модели, ни цены. `cars_seen` — наша копия данных, чтобы страницу проданной машины было чем
наполнить и из чего собрать запрос «покажи такие же».

Пишется двумя путями, оба upsert по `encar_id`: пассивно при каждом рендере карточки
(через `after()`, чтобы не задерживать ответ) и разовым бэкфиллом
`scripts/backfill-cars-seen.ts`.

Инварианты:

- ⚠️ Ботов при записи снимков НЕ фильтровать, хотя рука тянется. Снимок нужен ровно тем
  страницам, что получают трафик из поиска, а попасть в поиск страница может только после
  обхода Googlebot'ом — обход и есть тот рендер, который мы записываем. Отфильтруем ботов —
  снимки останутся только у машин, которые кто-то открыл руками, а это малая доля индекса.
  Обратный фильтр (`isbot` в `middleware.ts`) существует для аналитики и сюда не
  переносится.
- `sold_at` ставится ТОЛЬКО на строгий `null` от `fetchVehicleData`. Авария апстрима бросает
  `VehicleUpstreamError` и до этой ветки не доходит; непустой, но кривой ответ продажей
  тоже не считается — иначе сбой парсинга у Encar пометил бы живые машины проданными.
- Единицы: `price_manwon` хранится в 만원, КАК ОТДАЁТ ENCAR, без пересчёта. В воны —
  × 10000, ровно как это делает карточка. Не путать с запчастями, где `price_krw` — это
  настоящие воны.
- Троттлинг в памяти инстанса (1 час) стоит и на записи снимка, и на отметке продажи; ключи
  разведены префиксами `seen:`/`sold:`, иначе снимок съедал бы право отметить ту же машину
  проданной в том же часе. Id, не подходящие под `/^\d{6,10}$/`, отсекаются до похода в
  базу — в `/catalog/[id]` прилетает мусор из индекса и от сканеров.
- Модуль не бросает исключений НИКОГДА: карточка авто важнее снимка. Пока таблицы нет или
  Supabase лежит — только `console.error`.

#### Подписки «пришлём похожие»

Файлы: `src/lib/savedSearches.ts`, `sql/036_saved_searches.sql`.

Человек нажал кнопку на странице проданной машины → бот запоминает запрос → крон раз в
сутки пишет ему, когда подходящее появилось. Смысл в том, что на проданную карточку
приходят именно за тем, чего сейчас НЕТ в наличии.

Бот — существующий KMOTORS_form_bot, тот же `TELEGRAM_BOT_TOKEN`. Его `/start` уже
публичный и обрабатывается ДО гейта `isAdmin`, рядом с разбором `car_<id>`; отдельный бот
разнёс бы клиентский опыт по двум чатам. Метка `sold_<encar_id>` несёт всё нужное, поэтому
ни токенов, ни промежуточного роута создания подписки нет.

Инварианты — все найдены живыми тестами и в коде не видны:

- ⚠️ Новизна определяется по `manage.firstAdvertisedDateTime` из КАРТОЧКИ, а не по
  отсутствию `Id` в `seen_ids` ([постмортем](docs/postmortems.md)).
- Даты Encar отдаёт без зоны, время корейское — разбирать как `+09:00` явно, иначе
  `Date.parse` считает их UTC и сдвигает на 9 часов.
- `FETCH_LIMIT` общий для засева и крона, живёт в `savedSearches.ts`. Разойдутся — и на
  первом прогоне давно висящие объявления уедут человеку как новинки.
- `seen_ids` схлопывается (`compactSeen`), иначе копит дубли: замер на проде дал 111
  записей при 60 уникальных. Оставляем ПОСЛЕДНЕЕ вхождение — срез идёт с конца.
- Названия машин берутся из карточки (`manufacturerEnglishName` / `modelGroupEnglishName` /
  `gradeEnglishName` + `normalizeBrand`), а НЕ из листинга: в листинге только корейские
  ([постмортем](docs/postmortems.md)). Карточка и так запрашивается ради даты подачи,
  второго запроса не нужно.
- `parse_mode` HTML, имена приходят от Encar — экранировать `<` `>` `&`. Кривой тег роняет
  отправку целиком (Telegram отвечает `ok:false`).
- Апстрим не ответил (`failed`) — НЕ трогать ни `seen_ids`, ни `last_sent_at`: авария Encar
  молча съела бы новинки, зачислив их в «виденные» без отправки. По той же причине
  `seen_ids` пополняется только после УДАЧНОЙ отправки.
- Подписку не создаём, если Encar лёг: пустой засев = ложные новинки на первом прогоне.
- Отписка (кнопка `unsub:<id>`) сверяет `chat_id` — `callback_data` приходит от клиента,
  без сверки любой отписал бы чужую подписку по произвольному id. Обрабатывается до гейта
  `isAdmin`, как и `/start`. Массовая отписка — команда `/stop`.

Настройки (решение владельца): проверка раз в сутки, не чаще одного сообщения в сутки на
человека, не больше пяти машин в сообщении. Одинаковые запросы дедуплицируются по строке
`query` — из Encar тянутся один раз и раздаются веером.

### Каталог запчастей

Вход: `/[lang]/parts` и `/[lang]/parts/[slug]`. Блоки интерфейса в `src/app/parts/sections/`
(не под `[lang]/`): `PartsCatalog.tsx` (сервер, SSR первой страницы ради SEO) →
`PartsCatalogClient.tsx` (клиент, фильтры от URL) и `ProductDetailClient.tsx`. Подробности:
[docs/parts-pages-design-reference.md](docs/parts-pages-design-reference.md).

- Данные: `/api/parts/products` (пагинация, фасетные счётчики) ← `parts_products`.
- Совместимость с авто разъехалась по двум системам (см. «Жёсткие правила»): источник
  правды — `part_vehicles` + `vehicles` (страница товара, `/fitment`, сайтмапы,
  seo-generate); легаси `parts_fitment` + `parts_vehicle_models` — только чипсы фильтра по
  моделям в каталоге.
- Дизайн-токены страниц запчастей — CSS-переменные `--pn-*` в `src/app/globals.css`,
  отдельно от токенов `axis.*` в Tailwind, которыми пользуется остальной тёмный сайт.
- ⚠️ В `parts_products` 130 артикулов занимают несколько строк — это НЕ дубли записей и их
  НЕЛЬЗЯ сливать: одна деталь занесена по строке на каждый совместимый автомобиль. Поэтому
  в `[lang]/parts/[slug]/page.tsx` стоит `.limit(1)`, а не `.single()`, и в сайтмапе один и
  тот же `<loc>` повторяется. Разбор и следствия — [постмортем](docs/postmortems.md).

#### Пустая выдача каталога = точка потери клиента, а не служебное состояние

Нулевой результат поиска раньше означал «Ничего не найдено» — клиент делал вывод, что
детали нет, и уходил. Теперь при `products.length === 0` рендерится `NoResultsBanner.tsx`
(`src/app/parts/sections/`): оффер «привезём под заказ» + три пути в личку — заявка через
тот же `OrderModal` (`source: parts_no_results`, артикул из поиска подставляется в
`partNumber`, лид уходит в Telegram через `/api/telegram`) и прямые ссылки
WhatsApp / Telegram с готовым текстом запроса.

- Инвариант: строка счётчика над сеткой при `total === 0` остаётся ПУСТОЙ — «ничего не
  найдено» больше нигде не дублируется. Не возвращать `t("parts.catalog.noResults")` в
  results bar.
- Ключи баннера — `parts.catalog.miss.*` во всех четырёх локалях. Ключи `noResults` /
  `noResultsHint` остались в JSON для других мест — их наличие не значит, что баннер их
  использует.
- События `search_no_results` (с `search_term`), `no_results_request`,
  `no_results_messenger` — это метрика спроса на то, чего нет в базе; ей меряется, что
  закупать. Не переименовывать без причины.

#### Поиск — отправка ЯВНАЯ, и URL там пишется мимо роутера

Строка поиска на `/[lang]/parts` (`SearchBar` в `PartsCatalogClient.tsx` — тот инпут, что
внутри `#catalog`, не пилюля в Hero) отправляет запрос только по кнопке «Найти», по Enter,
по крестику очистки и по событию `parts:hero-search` (там пользователь уже нажал поиск,
второго клика не просим). Дебаунса нет вообще; не возвращать
([постмортем](docs/postmortems.md)).

Три вещи, которые в коде не видны и которые легко сломать обратно:

- `q` пишется через `window.history.replaceState`, а НЕ `router.push`. Серверный рендер
  `/[lang]/parts` от `searchParams` не зависит (их читает только `generateMetadata` ради
  noindex на отфильтрованных URL), а товары приходят отдельным клиентским fetch'ем в
  `/api/parts/products`. Значит `router.push` здесь — чистая переплата. Фильтры, сортировка
  и пагинация НАМЕРЕННО остались на `router.push`: там URL — источник правды для выборки, и
  через него же работают back/forward. Отсюда параметр `updateParams(updates, { replace })`.
- `updateParams` строит параметры из `window.location.search`, а не из `useSearchParams()`.
  После `replaceState` хук обновляется не синхронно, и следующий клик по фильтру уносил бы
  `q` из адреса.
- Состояние ввода живёт ВНУТРИ `SearchBar` (memo), наружу уходит только отправленное
  значение. В корневом компоненте оно перерисовывало бы на каждую букву 24 карточки,
  сайдбар с фасетными счётчиками и облако категорий.
- `updateFilters` всегда снимает `page`. Любой новый эффект, дёргающий `updateFilters`,
  обязан пропускать первый прогон — иначе заход на `/ru/parts?page=5` перекинет сам себя на
  первую страницу.

#### Кеширование — revalidate и generateStaticParams это РАЗНЫЕ ручки

Отсутствие `generateStaticParams` — вот что не даёт сборке генерить 50k × 4 языка страниц;
маршрут при этом рендерится по требованию при первом визите. `revalidate` к объёму сборки
отношения не имеет: он задаёт, сколько отрендеренная страница живёт в кеше.

Текущие значения: `/[lang]/parts` 3600, `/[lang]/parts/[slug]` 86400,
`/[lang]/parts/category/[slug]` 3600, `/[lang]/fitment/[brand]/[slug]` 86400.

TTL внутренних `unstable_cache` (parts-catalog-data 3600, parts-product 3600,
parts-top-links 86400 и прочие) подчинены `revalidate` маршрута: если сегмент не
перерендеривается, эти TTL декоративны — их некому опросить. Настраивать внутренний кеш,
не посмотрев на `revalidate` сегмента, бессмысленно.

Инвариант про цену и `revalidate ≤ 86400` — в «Жёстких правилах». Два ложных следа при
диагностике кеша (пометка `ƒ Dynamic` и заголовок `Cache-Control: private`) и единственный
надёжный способ проверки — [постмортем](docs/postmortems.md).

### Блог — генерация статей (blog_topics → blog_posts)

`/api/blog-generate` (Gemini 2.5-flash напрямую, не через `llm.ts`): берёт из `blog_topics`
самую приоритетную тему со `status='pending'` → генерирует RU → переводит на EN (ko/ka/ar
не генерируем, их страницы noindex) → обложка с Pexels → вставка в `blog_posts`. Замер на
проде: ~45 сек на статью.

- Пост создаётся ЧЕРНОВИКОМ (`published: false`). На сайт он попадает только после кнопки в
  Telegram (callback `publish:` в telegram-webhook). Генерация ≠ публикация — «постов нет»
  может значить «черновики есть, их не одобрили».
- Квалити-гейт внутри ретрая: валидный JSON + минимум 700 слов + обязательная
  markdown-таблица. Три попытки.
- Провал НЕ сжигает тему: приоритет понижается на `PRIORITY_PENALTY`, `'failed'` ставится
  только когда приоритет исчерпан ([постмортем](docs/postmortems.md)).
- Пустой пул и остаток `<= LOW_POOL_THRESHOLD` шлют уведомление в Telegram.
- Статусы `blog_topics`: `pending` / `generated` / `skipped` / `failed`.

### Расписания — живут на VPS, а НЕ в vercel.json

Каждое задание = скрипт в `scripts/` + строка в системном планировщике на VPS. Строка для
crontab лежит в шапке самого скрипта. Не возвращать блок `crons` в `vercel.json`
([постмортем](docs/postmortems.md)).

| Задание | Скрипт / эндпоинт | Расписание | Гейт |
|---|---|---|---|
| Черновик статьи блога | `scripts/blog-generate-cron.sh` | `0 10 */3 * *` | x-poster-secret |
| Синхронизация RSS-новостей | `scripts/rss-sync-cron.sh` | `0 9 * * *` | x-poster-secret |
| Сбор статистики GSC | `scripts/seo-collect-cron.sh` | ежедневно | x-seo-secret |
| Автопостинг авто в Telegram | `/api/poster/run` (systemd timer) | по окну публикации | x-poster-secret |
| Рассылка подписок «похожие» | `scripts/subscriptions-cron.sh` | `0 11 * * *` | x-poster-secret |

Секретов два, не больше. `POSTER_CRON_SECRET` (заголовок `x-poster-secret`) закрывает
`/api/poster/run`, `/api/poster/parts/run`, `/api/rss-sync`, `/api/blog-generate` и
`/api/subscriptions/run`. `SEO_CRON_SECRET` (заголовок `x-seo-secret`) закрывает
SEO-пайплайн. `CRON_SECRET` больше не используется нигде — он был задан только в README и
ни разу в окружении.

### Сайтмапы — краул-бюджет делится между авто и запчастями, и это не поровну

Мастер-индекс `src/app/sitemap.xml/route.ts` собирает: `sitemap-main.xml` (статические
страницы × 4 языка + модельные + индексируемые категории запчастей), `sitemap-blog.xml`
(только ru+en, остальные языки noindex), `sitemap-fitment.xml` (поколения с
`parts_count >= 10`), затем `sitemap-parts/1..N` (по 1 000 товаров) и
`sitemap-catalog/1..N` (по 200 машин). `robots.ts` отдаёт Google ТОЛЬКО `sitemap.xml` —
дочерние файлы отдельно не подаются.

Соотношение сил: запчастей ~48 700 URL, машин 2 000. Запчасти вечные, машина одноразовая
(продалась → Encar 404 → noindex). Поэтому у каталога авто приоритеты сознательно занижены,
и это НЕ баг:

- Карточки машин отдаются БЕЗ `<lastmod>` и БЕЗ `<changefreq>`, с `priority` 0.5 (ниже
  запчастей с 0.7) ([постмортем](docs/postmortems.md)).
- `CATALOG_MAX_CARS` в `sitemap.xml/route.ts` и `MAX_OFFSET` в
  `sitemap-catalog/[page]/route.ts` — ОДНО И ТО ЖЕ число (2 000), меняются только вместе,
  иначе индекс сошлётся на пустые файлы. 2 000 — наш выбор ради краул-бюджета, а не предел
  Encar.
- ⚠️ 2 000 ограничивает РАЗМЕР ФАЙЛА, а не набор машин: верхние 2 000 позиций выдачи Encar
  обновляются целиком за две минуты, так что сайтмап — это скользящее окно по всему пулу в
  155 тысяч. Следствия и незакрытые замеры — в
  [docs/open-questions.md](docs/open-questions.md).
- Порядок выдачи Encar стабилизировать нечем, поэтому один файл содержит ~200 URL на ~180
  уникальных Id, и между файлами дубли тоже есть. Google дедуплицирует URL по индексу
  целиком, так что это терпимо. Настоящее лечение — отдавать сайтмап из своего хранилища
  ([docs/open-questions.md](docs/open-questions.md)).

## Внешние системы

### Encar API — замеры (29.07.2026, curl с сервера)

- Листинг: 70–90 мс, до 200 записей за запрос. Троттлинга на 25 запросах подряд нет,
  user-agent не обязателен.
- Прокси на Render режет выдачу до 20 записей независимо от запрошенного лимита — отсюда
  10 запросов бэкфилла напрямую против 100 через прокси.
- Проверять конкретную машину — `api.encar.com/v1/readside/vehicle/{id}` (200 живая /
  404 проданная). Фильтр `Id.<id>.` в поисковом запросе отдаёт HTTP 404 (проверено в обеих
  кодировках скобок); именно он стоит в `useFavoritesSync.ts`, из-за чего алерты по цене в
  избранном не работали ни разу ([постмортем](docs/postmortems.md)).
- Глубокие offset'ы молча клампятся примерно после ~50k, а сортировку стабилизировать
  нечем — детали и направление решения в
  [docs/open-questions.md](docs/open-questions.md).

### Google Search Console

- API доступен из скриптов через сервисный аккаунт: переменные `GSC_SA_JSON` (ключ
  сервисного аккаунта, JSON одной строкой) + `GSC_SITE_URL=https://www.kmotors.shop/`.
  Хелпер: `src/lib/gsc.ts` (JWT → REST `searchAnalytics/query`), `google-auth-library`
  установлена. Ручной экспорт лежит в
  `./https___www.kmotors.shop_-Performance-on-Search-2026-07-12/`, но это снимок — за
  актуальными цифрами ходить в API.
- ⚠️ Клики и показы из Кореи (`country = "kor"`) — это собственный трафик владельца, а НЕ
  реальные пользователи. ВСЕГДА исключать Корею из любого SEO-анализа
  (`dimensionFilterGroups` country notEquals `"kor"`). Корея давала ~43% кликов в
  трёхмесячном окне, так что нефильтрованные тоталы — и особенно видимая позиция и показы
  калькулятора — сильно искажены.

### Корея закрыта в ДВА независимых слоя

Изменение одного слоя не влияет на другой.

- **Слой 1, Cloudflare WAF** (вне репозитория, отсюда его не прочитать и не изменить):
  кастомное правило блокирует запросы из Кореи на эдже. Исключение — Skip-правило с
  бо́льшим приоритетом по cookie, выражение `http.cookie contains "my_secret_key=<value>"`.
  ЗНАЧЕНИЕ НАМЕРЕННО НЕ ЛЕЖИТ В ЭТОМ ФАЙЛЕ: репозиторий на GitHub ПУБЛИЧНЫЙ (проверено
  через `gh repo view` — visibility PUBLIC), поэтому всё закоммиченное здесь навсегда
  доступно всему миру, включая историю git и любой форк. Хранить в `.env` / менеджере
  паролей. Чтобы использовать — поставить cookie один раз в браузере для kmotors.shop либо
  передать `--cookie "my_secret_key=<value>"` в curl; код приложения его не читает.
- ⚠️ **Область блока — ТОЛЬКО каталог авто, не весь сайт** (замерено 29.07.2026 с
  корейского IP): 403 отдают `/{lang}/catalog` и `/{lang}/catalog/{id}`; `/{lang}`,
  `/{lang}/parts`, `/{lang}/blog`, `/{lang}/calculator`, `/sitemap.xml`, `/robots.txt` и
  `/api/*` открыты и проверяются без всякой cookie. Пришедший из Кореи 403 на карточке авто
  — это работающее правило, а не сломанный прод; не искать причину в приложении.
- **Слой 2, скрытие ссылок в приложении:** `CATALOG_BLOCKED_COUNTRIES = ["KR"]` в
  `src/hooks/useCountry.ts`. `middleware.ts` копирует `cf-ipcountry` в читаемую браузером
  cookie `x-user-country` (24ч), `useCountry()` читает её на клиенте, и шесть компонентов
  убирают точки входа в каталог (Header, Footer, Home/Main, Home/NavCards,
  Home/PopularModels, CTA в статье блога). Только авто — запчасти остаются видимыми.
- Слой 2 косметический, это НЕ средство контроля доступа: он только прячет ссылки.
  `/[lang]/catalog` отвечает 200 кому угодно, кто дошёл до origin, а cookie тривиально
  правится в devtools. Не считать это контролем доступа и не «чинить» избыточность между
  слоями.
- Следствие для исключений: Skip-cookie Cloudflare проводит через эдж, но ссылки в навигации
  всё равно останутся скрытыми — слой 2 смотрит на `x-user-country` и про обход ничего не
  знает. Реальный вайтлист = править оба места.
- Каталог авто закрыт для Кореи намеренно (безопасность + SEO): `/ko/*` 301-редиректится в
  `/en/*` (`middleware.ts`), чтобы SEO-вес легаси корейских URL консолидировался на `/en`.
  Не помечать как баг ни редирект ko→en, ни отсутствие `ko` в hreflang, ни остаточные
  клики по `/ko/` в GSC.
