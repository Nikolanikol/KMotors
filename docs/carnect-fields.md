# carnect — единая карточка машины: поля и кто их видит

Черновик на утверждение владельцу (02.10.2026). Шаг 3a плана: прежде чем
рисовать страницу машины, договориться, ЧТО на ней стоит и что из этого видит
клиент.

## Почему нужна стандартизация

Шесть источников отдают РАЗНОЕ: у Autobell сканы техпаспорта и юридическая
чистота, у K Car акт осмотра с окрашенными панелями, у Lotte лист узлов
группами, у HeyDealer страховая история и шины, но нет дня торгов. Одни и те же
вещи называются по-разному (`legalStatus` у Autobell, `legal` у K Car), а
листы осмотра приходят в разных формах.

Отсюда решение: **одна модель карточки и по адаптеру на источник.** Адаптер
(аукцион → карточка, HeyDealer → карточка) — единственное место, которое знает
про форму источника. Страница рисует только карточку, а блок без данных просто
не показывается. Новое поле у carnect = правка одного адаптера, а не страницы.

Источник формы полей — живые ответы, снятые при разведке 02.10.2026
(`src/lib/carnect/types.ts`, `heydealer.ts`). Где покрытие по площадке не
проверено, стоит «?» — сверить на панели «Все поля» страницы лота.

## Поля карточки

Обозначения: ✓ есть, — нет, ? не сверено. **К** — видит клиент, **М** — только

## Решения владельца (02.10.2026)

1. **VIN, госномер, номер лота и аукционный дом клиент ВИДИТ.** Осознанно:
   прозрачность важнее риска, что машину найдут на площадке напрямую.
2. **Только нам:** скан техпаспорта, число ставок, цена после торгов,
   корейские замечания инспектора и продавца, таблица всех полей, сырой JSON.
3. **Скан листа осмотра (Lotte, SK, Autobell) клиент ВИДИТ** — у этих площадок
   схема кузова есть только на нём.
4. **Расшифровка оценок осмотра нужна** — таблица по каждой площадке.
5. **Отчёт осмотра кузова обрабатываем в единую схему** — см. ниже.

## Схема кузова — единая для всех источников

Площадки отдают повреждения кузова по-разному: K Car структурой
(`panelDiagram`, акт осмотра), HeyDealer списком «деталь → ремонт»
(`accidentDiagram.repairs`), часть площадок — только готовой картинкой
(скан листа у Autobell, диаграмма у витрины dokanmazad). Сводим к одному виду:

- **Наш словарь панелей** (~25): капот, крыша, багажник, передний и задний
  бампер, крылья, двери и пороги с каждой стороны, задние крылья (квотеры),
  стойки, лонжероны, панели пола, рамка радиатора…
- **Наш словарь действий**: замена, сварка, окрас, требует ремонта.
  Порядок тяжести такой же: замена и сварка — силовые, окрас — косметика.
- **Адаптер на источник** переводит его коды деталей и действий в наш словарь.
  Незнакомый код не теряется — уходит строкой в список «прочее» и в лог.
- **Отрисовка своя:** SVG-силуэт машины сверху, панели закрашены по действию,
  под ним список «Капот — замена» с легендой. Внешний вид не зависит от того,
  какая площадка прислала данные.
- Где структуры нет, а есть только картинка, показываем картинку как есть.
- Силовые элементы (лонжероны, стойки, пол) выделяются отдельно: для покупателя
  это главное, окрашенное крыло рядом с заменённым лонжероном — мелочь.

### Что реально приходит (срез 02.10.2026: по 4 лота на площадку, 3–4 машины на тип HeyDealer)

| Источник | Структура по кузову | Что ещё |
|---|---|---|
| K Car | `panelDiagram.marks`: `key` («0407»), `nameEn`, `code` X замена / W рихтовка-сварка / G регулировка, `when` past | число внешних панелей в акте |
| Autohub | `panelDiagram.marks`: `key` («EX_FRONT_BUMPER», «FR_STEP_LEFT»), `code` XX замена (была) / X нужна замена / R нужен ремонт, `when` past / current; группа Glass — стёкла и зеркала | страховая история (`insurance`), 13 групп осмотра узлов |
| HeyDealer Zero, Instant | `accidentDiagram.repairs`: `partKey` («fender_front_driver», «side_sil_pannel_driver»), `repair` Exchange / Weld | **толщиномер** `paint.measurements`: по панелям normal / slightly_thick / very_thick / extremely_thick — то есть окрас виден даже там, где ремонта не заявлено; шины, течи, ошибки на приборке |
| HeyDealer Self | нет | только текст продавца: «Body Panel : 4 panels need repair» |
| Lotte, SK | НЕТ — только скан листа осмотра (`inspectionSheetImage`) и строка замечаний | лист узлов в двух группах, оценка |
| Autobell | НЕТ — только скан листа осмотра и метка `accidentTag` | страховая история, «ущерб по страховке» диапазоном |

Отсюда два вида данных, и смешивать их нельзя:

- **что делали** (`when: past`, HeyDealer repairs, толщиномер) — история машины;
- **что требует работы сейчас** (`when: current` у Autohub) — будущие расходы
  покупателя.

Единая схема действий: замена · сварка/рихтовка · окрас (толщиномер) ·
регулировка — для истории; нужна замена · нужен ремонт — для текущего.

⚠️ У Lotte, SK и Autobell схемы кузова в данных нет — у них она живёт только на
скане листа осмотра. Значит, для этих площадок скан листа осмотра — это и есть
схема кузова, и прятать его от клиента значит оставить клиента без неё.

⚠️ Попутная находка: на странице лота у Lotte `startKrw` ЗАПОЛНЕН (₩12 600 000
у всех четырёх), хотя раньше было «всегда 0». Проверить список и синк — если
цену отдают и там, Lotte уходит из `price_kind = none`.
