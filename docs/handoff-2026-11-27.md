## 7. Как работать дальше (правила владельца и безопасный старт)

- Отвечать по-русски; смотреть на решения владельца критически (один раз, с цифрами), дальше выполнять.
- Делимые задачи — субагентам параллельно (`isolation: "worktree"`, ветка от `integration/cleanup`, в брифе файлы,
  критерий готовности, запрет push); результат проверять самой (diff, `tsc`, lint, vitest), не по отчёту.
- `git push` и `gh pr merge` — только по явному «да» владельца в текущей сессии; работа в feature-ветках.
  Выкатка = `git push origin <ветка>:main` (fast-forward), перед ней — `git fetch` и тег на прежний прод.
- Проверка перед «готово»: `npm run lint`, `npx tsc --noEmit` (игнорировать устаревший `.next/types/validator.ts`),
  `npx vitest run`. Сборка ошибок не ловит (`ignoreBuildErrors`). Признак нового деплоя — URL, которого
  не было в прежней сборке, а не главная.
- **Безопасный локальный просмотр.** `npm run dev` из основной папки бьёт в продовую Supabase (`.env`) и пишет в
  `cars_seen`. Вместо этого: `git worktree add --detach <папка> <ветка>`, симлинк `node_modules`, в `.env.local`
  только `grep '^NEXT_PUBLIC_' .env`, запуск `npx next dev -p 3000` (без `--turbopack`: он не принимает симлинк
  `node_modules`). После — `git worktree remove`. Запчасти, оплата и админка на таком стенде не работают.
- Сначала самый короткий путь: данные — Supabase SQL Editor, один `SELECT`; упёрся в права — сказать владельцу,
  каким одним действием достать, не искать обходы.
