# Журнал индексации и видимости в Google

Файл существует ради одного: **не проводить расследование заново.** Каждый замер
кладётся сюда датированным блоком, и следующая проверка становится СРАВНЕНИЕМ с
предыдущей, а не выводом причинно-следственных связей с нуля.

Разбор, из которого всё выросло, — в CLAUDE.md, раздел «Карточки запчастей ТОНКИЕ».
Здесь только измерения, метод и что с чем сверять.

## Как снимать замер

Половины две, и вторую автоматизировать нечем.

**1. Поисковая аналитика — скриптом.** Отдаётся через API:

```bash
node scripts/seo/indexation-snapshot.mjs      # печатает готовый блок для этого файла
node scripts/seo/parts-demand.mjs             # пересобирает docs/parts-demand-top300.md
```

**2. Число страниц в индексе — РУКАМИ.** ⚠️ Отчёт «Страницы» (бывший Coverage) в API
Search Console НЕ ОТДАЁТСЯ вообще: ни числа в индексе, ни разбивки причин. Только
выгрузка человеком:

> Search Console → Индексирование → **Страницы** → кнопка **Экспорт** (вверху справа)
> → «Загрузить CSV». В архиве четыре файла, нужны «Диаграмма» и «Критические проблемы».

Класть в `data/gsc/coverage-chart-ГГГГ-ММ-ДД.csv` и `coverage-reasons-ГГГГ-ММ-ДД.csv`.
⚠️ Имена файлов в архиве русские и в кодировке, которую `unzip` не берёт («Illegal byte
sequence») — распаковывать питоном через `zipfile`, декодируя `cp437 → utf-8`.

⚠️ **Отчёт «Страницы» отстаёт примерно на две недели.** Выгрузка 04.10.2026 кончалась
21.09. Спрашивать его про событие недельной давности бесполезно — данных ещё нет.

## Три ловушки измерения — на каждую я уже попался

- ⚠️ **Группировка по `page` в GSC занижает в десятки раз.** Порог приватности
  выбрасывает адреса с малым числом показов, и сумма перестаёт быть суммой: за одну
  неделю по измерению `page` вышло 26 показов, по `device` за тот же период — 2447.
  Тоталы брать ТОЛЬКО по `date` / `device` / `country`; `page` годится лишь для структуры.
- ⚠️ **Проверка выдачи руками из Кореи меряет КОРЕЙСКУЮ выдачу.** Параметр `gl=ru` не
  помогает, Google берёт регион по IP. Живой случай: `256003C660` из Кореи не нашёлся ни
  на одной из трёх страниц даже с `filter=0`, а GSC по тому же запросу показывает позицию
  8 в России. Проверять только через GSC (`query` × `country` × `page`) или из VPN в
  целевой стране.
- ⚠️ **Позиция и широта охвата — РАЗНЫЕ величины.** Позиция всё время держалась 7–9 и не
  падала ни разу. Падало число артикулов, по которым нас вообще показывают. «Ранжируется
  хорошо» и «показывается часто» здесь означают противоположные вещи.

Доля падает ровно, неделя за неделей: 62.0 → 52.9 → 48.9 → 44.4 → 42.5 → 40.1 → 36.5 → 33.5.

## Что проверять в следующий раз

Порядок: сперва скрипт, потом свежая выгрузка (если прошло больше двух недель).

| показатель | база 04.10.2026 | что значит рост | что значит падение |
|---|---|---|---|
| артикулов в неделю | 5 | механизм пошёл | продолжаем терять |
| показы в неделю | 130 | — | — |
| доля в индексе | 33.5% | приток одноразовых адресов остановлен | знаменатель всё ещё растёт |
| всего известно Google | 378 831 | сайтмап машин НЕ помог | помог |
| `noindex` | 104 520 | проданные машины копятся | куча рассасывается |
| просканирована, но не проиндексирована | 88 223 | качество не принято | принято |

**Первым делом смотреть «всего известно Google».** Если число перестало расти — значит
сайтмап из `cars_seen` (02.10) сработал и приток одноразовых адресов прекращён. Это самая
ранняя наблюдаемая реакция, раньше показов и раньше доли в индексе.

⚠️ Машины из сайтмапа обходятся не мгновенно: 02.10 все восемь проверенных адресов были
«URL неизвестен Google, обход НИ РАЗУ». Первый признак, что заработало, — смена этого
статуса на «обнаружена» в URL Inspection. Проверять не раньше чем через 5–7 дней после
02.10.
